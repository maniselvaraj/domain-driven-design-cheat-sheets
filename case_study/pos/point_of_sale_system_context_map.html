DDD Standard Notation Reference
U (Upstream) / D (Downstream) Customer-Supplier relationship. Upstream defines the interface, downstream conforms. Arrow points downstream (direction of dependency).
ACL (Anticorruption Layer) Protects downstream context from upstream changes. Translates external models to domain concepts. Critical for payment gateways, tax authorities, and supplier integrations.
PL (Published Language) Well-documented shared language between contexts. Implemented as domain events. Upstream publishes events, multiple downstreams consume for notifications and alerts.
CF (Conformist) Downstream accepts upstream model as-is. No translation. Used for Analytics consuming all events - cost of ACL exceeds benefit for read-only analytics.
Core Domain (Red) Strategic competitive advantage. Transaction Processing, Inventory Management, Product Catalog, and POS Console receive maximum investment. Complex business rules unique to retail POS.
Supporting Subdomain (Blue) Necessary for operations but not primary differentiator. Fiscal Compliance, Customer Management, Purchasing, and Analytics support core operations with business-specific logic.
Generic Subdomain (Gray) Solved problem available off-the-shelf. Payment Processing, Notifications, and Account Management should be purchased, not built. Use established providers for PCI compliance and reliability.
Aggregate Root Entry point for all operations on the aggregate. Enforces business invariants (transaction totals balance, inventory can't go negative, payment state transitions are valid).
Value Object (VO) Immutable object defined by attributes. No identity. Examples: Address, PaymentToken, DigitalSignature, PriceRule. Shared concepts across aggregates.
Entity Object with identity that persists over time. Mutable. Identity matters more than attributes. Examples: SaleLineItem, TransactionLine, InvoiceLineItem.
Transaction Orchestration Transaction Context coordinates distributed operations across Payment, Inventory, and Fiscal Compliance using Saga pattern with compensating actions.
Event-Driven Communication Contexts communicate through domain events for loose coupling, scalability, and audit trail. Events enable eventual consistency and multiple consumers.
